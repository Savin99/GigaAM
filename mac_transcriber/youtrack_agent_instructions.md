# Инструкция headless-агенту: read-only сверка встречи с YouTrack

Эта инструкция используется в двух ОТДЕЛЬНЫХ проходах Claude Opus 5. YouTrack
доступен не модели, а Python-оркестратору: модель готовит поисковые намерения или
сравнивает уже полученных кандидатов. Результат каждого прохода — только указанный
JSON-файл.

## Проход 1: извлечение поисковых намерений

Прочитай `agent_input.json` целиком. Выдели не более 12 сущностей, для которых имеет
смысл искать задачу в трекере:

- реальные поручения и следующие шаги;
- принятые решения;
- проблемы, баги и блокеры;
- обсуждаемые функции или изменения продукта;
- явные упоминания задач.

Не ищи задачи для приветствий, общих рассуждений и методологии без рабочего объекта.
Каждое намерение должно опираться на реальные `segment_id`. Учитывай ошибки ASR:
сформируй 1–3 коротких поисковых формулировки с синонимами, объектом и действием.
Формулировки должны быть обычным текстом без `project:`, `State:`, операторов и других
элементов языка запросов YouTrack.

Запиши `youtrack_intents.json`:

```json
{
  "intents": [
    {
      "kind": "explicit_issue|action_item|decision|problem|feature",
      "summary": "что именно обсуждалось",
      "queries": [
        "оборудование дополнительные поля документы",
        "поля для фронта ручка документов"
      ],
      "segment_ids": ["S0142", "S0143"]
    }
  ]
}
```

Не выдумывай номера задач. Даже если предполагаешь конкретный ID, опиши смысл —
Python отдельно обработает номера, буквально присутствующие в транскрипте.

## Проход 2: проверка кандидатов

Прочитай целиком:

- `agent_input.json`;
- `youtrack_candidates.json`.

Для каждого намерения сравни содержание цитированных сегментов с кандидатами,
у которых в `intent_ids` есть это намерение. Оцени совпадение по независимым
признакам:

- `explicit_issue_id` — только если кандидат получен через `explicit_id`;
- `same_object` — совпадает рабочий объект;
- `same_action` — совпадает требуемое изменение или действие;
- `same_component` — совпадает компонент/подсистема;
- `same_deliverable` — совпадает ожидаемый результат;
- `same_person` — совпадает явно названный исполнитель;
- `same_parent_epic` — контекст эпика подтверждает связь;
- `same_time_window` — временной контекст действительно полезен.

`confirmed` допустим, если есть `explicit_issue_id` либо минимум два независимых
содержательных признака и нет противоречий. При недостатке данных ставь `possible`.
Неподходящих кандидатов ставь `rejected`. Текущий статус задачи не подменяет содержание
встречи: отдельно учитывай, что состояние YouTrack могло измениться после записи.

Можно выбирать ТОЛЬКО `issue_id` и `intent_id`, реально присутствующие в
`youtrack_candidates.json`, и только реальные `segment_id` соответствующего намерения.

Запиши `youtrack_verification.json`:

```json
{
  "matches": [
    {
      "intent_id": "YT001",
      "issue_id": "CH-594",
      "decision": "confirmed|possible|rejected",
      "signals": ["same_object", "same_action"],
      "conflicts": [],
      "segment_ids": ["S0142", "S0143"],
      "rationale": "краткое объяснение совпадения или сомнения"
    }
  ]
}
```

Не создавай, не обновляй и не комментируй задачи. Не запускай команды и не записывай
никаких других файлов.
